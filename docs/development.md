# Development

## Repository layout

```text
.
├── packages/
│   ├── cli/                     Private workspace with TypeScript source and tests
│   ├── find-blind-spots/        Publishable read-only analysis skill payload
│   ├── project-foundation/      Publishable foundation skill payload
│   ├── run-claude-review-loop/  Publishable Claude review-loop payload
│   ├── run-codex-review-loop/   Publishable independent review-loop payload
│   ├── run-discovery-interview/ Publishable interview skill payload
│   ├── run-qwen-review-loop/    Publishable Qwen review-loop payload
│   ├── run-subphase/            Publishable bounded subphase-execution payload
│   ├── teach/                   Publishable standalone teaching-workspace payload
├── dist/                    Bundled Bun entry point, generated by the build
├── docs/                    User and maintainer documentation
├── scripts/                 Package verification and shared-reference sync
├── shared/                  Canonical sources for reference files copied into several payloads
└── package.json             Public npm package
```

The public package is the repository root. Workspace packages are private implementation boundaries.

## Setup

```bash
bun install --frozen-lockfile
```

## Commands

```bash
bun run typecheck
bun run lint
bun test
bun run build
bun run verify:skills
bun run verify:docs
bun run verify:package
bun run sync:shared
bun run check
```

`verify:skills` checks frontmatter, invocation policy, UI metadata, size, placeholders, local
resource links, and shared-reference drift for all eight payloads. `verify:docs` checks public
Markdown structure, local links, changelog state, and package metadata.
`verify:package` inspects the exact file manifest produced by npm, the tool used for publishing.
`bun run check` runs it as part of the release-level local verification command.

## Architecture

- `agents.ts` owns agent definitions, discovery paths, and platform user-data paths.
- `skills.ts` is the single registry of packaged skills. A registry key is also the package,
  target, managed-store, and receipt ID.
- `scripts/shared-references.ts` maps each canonical file under `shared/` to the payload copies
  generated from it. A payload stays self-contained because a user can install one skill without the
  others, so shared normative text ships as a copy; the registry is what keeps the copies from
  drifting apart.
- `topology.ts` converts intended agents into the smallest native target set.
- `payload.ts` hashes, receipts, and atomically materializes one packaged skill.
- `installations.ts` inspects physical and linked installations.
- `operations.ts` implements install, update, removal, migration, and conflict policy hooks.
- `suite.ts` combines preflight results and provides rollback across a multi-skill confirmation.
- `transaction.ts` snapshots every touched path and performs compensating restore on failure.
- `ui.ts` implements the custom Clack Core rendering and diff viewer.
- `index.ts` owns interactive flows and user-facing policy.

Filesystem logic is UI-independent so tests can use isolated temporary homes and projects.

## Adding a skill

1. Scaffold and validate the skill with the repository's supported skill-creation workflow.
2. Add a private workspace under `packages/<skill-id>` with `SKILL.md` and only the optional resource
   directories it needs.
3. Add the same stable ID and its display metadata to `SKILLS` in `skills.ts`; `SkillId` and
   `SKILL_IDS` are derived automatically.
4. Declare `policy.allow_implicit_invocation` in `agents/openai.yaml`. A skill that must not fire on
   its own also needs `disable-model-invocation: true` in `SKILL.md`; verification rejects the two
   disagreeing. If the skill reuses text under `shared/`, register its copy in
   `scripts/shared-references.ts` and run `bun run sync:shared`.
5. Run skill and package verification. The package globs and verification scripts discover the
   registered payload automatically.
6. Test independent target/store paths, optional payload directories, suite rollback, update, and
   removal.
7. Update installation, target, update, removal, and release documentation.

## Adding an agent

1. Add its definition and documented paths to `agents.ts`.
2. Add its ID to `AGENT_IDS` and define project-scope support explicitly.
3. Update topology priority and shared discovery coverage.
4. Add isolated filesystem tests for user, project, copy, link, update, and partial removal.
5. Add the primary source and review date to `docs/compatibility.md`.
6. Update every public target table.

## UI principles

- Ask one decision at a time.
- Keep one blue accent plus semantic success, warning, and error colors.
- Show a preview before mutations.
- Keep destructive defaults conservative.
- Support `NO_COLOR`, keyboard-only use, cancellation, narrow terminals, and ASCII fallbacks.
- Use motion only as terminal feedback supplied by the prompt primitive, never as decoration.
- Keep every visible string concise and avoid decorative punctuation.
