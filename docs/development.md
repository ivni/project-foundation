# Development

## Repository layout

```text
.
├── packages/
│   ├── cli/                 Private workspace with TypeScript source and tests
│   └── skill/               Private workspace with the publishable raw skill payload
├── dist/                    Bundled Bun entry point, generated by the build
├── docs/                    User and maintainer documentation
├── scripts/                 Package verification
└── package.json             Public npm package
```

The public package is the repository root. Workspace packages are private implementation boundaries.

## Setup

```bash
bun install --frozen-lockfile
```

## Commands

```bash
bun run typecheck
bun run lint
bun test
bun run build
bun run verify:docs
bun run verify:package
bun run check
```

`verify:docs` checks public Markdown structure, local links, changelog state, and package metadata.
`verify:package` inspects the generated tarball. `bun run check` runs both as part of the release-level
local verification command.

## Architecture

- `agents.ts` owns agent definitions, discovery paths, and platform user-data paths.
- `topology.ts` converts intended agents into the smallest native target set.
- `payload.ts` hashes, receipts, and atomically materializes the packaged skill.
- `installations.ts` inspects physical and linked installations.
- `operations.ts` implements install, update, removal, migration, and conflict policy hooks.
- `transaction.ts` snapshots every touched path and performs compensating restore on failure.
- `ui.ts` implements the custom Clack Core rendering and diff viewer.
- `index.ts` owns interactive flows and user-facing policy.

Filesystem logic is UI-independent so tests can use isolated temporary homes and projects.

## Adding an agent

1. Add its definition and documented paths to `agents.ts`.
2. Add its ID to `AGENT_IDS` and define project-scope support explicitly.
3. Update topology priority and shared discovery coverage.
4. Add isolated filesystem tests for user, project, copy, link, update, and partial removal.
5. Add the primary source and review date to `docs/compatibility.md`.
6. Update every public target table.

## UI principles

- Ask one decision at a time.
- Keep one blue accent plus semantic success, warning, and error colors.
- Show a preview before mutations.
- Keep destructive defaults conservative.
- Support `NO_COLOR`, keyboard-only use, cancellation, narrow terminals, and ASCII fallbacks.
- Use motion only as terminal feedback supplied by the prompt primitive, never as decoration.
- Keep every visible string concise and avoid decorative punctuation.
